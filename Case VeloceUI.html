02

THE PROBLEM

MOTION IS EITHER MISSING OR 60 kB.

Most component kits ship static. Teams then bolt on an animation library, pay for it in bundle size and learning curve, and still end up with inconsistent fades hand-rolled per screen.

Veloce's bet: choreography is a design token. Give every component the same easing vocabulary — press 120ms, lift 200ms, stagger 40ms — and express it entirely in CSS.

03

THE BUILD

TOKENS → MOTION → 36 COMPONENTS.

MOTION AS CUSTOM PROPERTIES

--v-dur, --v-ease, --v-stagger. Components read them; themes override them. Reduced motion zeroes them all in one rule.

ACCESSIBLE BY DEFAULT

Focus-visible rings, ARIA roles, keyboard flows for every overlay. WCAG 2.2 AA audited across all 36 primitives.

THEMABLE ACCENTS

Light, dim, dark + three accent hues. The switcher in the docs is the same API consumers get.

DOCS THAT DEMO

Each page links a Figma example, GitHub example and Storybook story. Docs are built with the library itself.

04

FEATURE DEEP-DIVE

CHARTS ARE COMPOSED, NOT CONFIGURED.

A ChartContainer owns data and scales; axes, grid, each series, tooltip, crosshair and legend are their own child components. Lines draw in along their path (600ms swift-out), points settle last, and the crosshair follows the pointer with the same easing every other Veloce component uses. The docs' tree view lets you click any node to isolate what it renders.

THE IMPACT

WHAT I'D TELL A CLIENT

Polish that scales comes from systems, not heroics. Decide the motion once, encode it, and every new screen inherits it for free.
